## 1. 共有する部品はいつも本体と同じ版で取り込む

**【決定】** 2026-11-04 作者の裁定（母艦「0.125.4 母艦引継ぎ」から伝達）：本体と共通の部品（`src/models/`・`src/core/`）は「いつも本体と同じ版」で取り込む。本体の版が上がるたびに同じ部品を取り込み、モバイル版を出し直す。

**理由**：作品フォルダーの `設定/` は GitHub で同期するので、本体とモバイル版が同じ台帳を読み書きする。古い部品は台帳の知らない欄を落として書き戻すので、モバイル版が古いままだと、本体で増えた欄が同期で消える。0.123.0〜0.125.4 で投稿の台帳（`models/posting.ts`）に増えた欄（`posts[]` の bodyHash・titleHash・siteEpisodeId・postRef、台帳の revisions、siteFacts の siteWorkNumber）はその例で、本体の注記にも「この欄を知らない古い版が保存すると消える」とある。

`src/ai/`・`src/prompts/` も共有する（設計書 2.2）。台帳を書く部品ではないが、同じ版で取り込む。版をばらばらに持つと、どの組み合わせで確かめたか分からなくなるためである。

## 8. git の試作：取得（2026-11-06。枝 `proto/isomorphic-git`、PR #5 の上に積んだ）

母艦の指示の順（isomorphic-git で公開リポジトリの取得を試作 → 差し替えの形を決める → 送信はデバイスフロー）の1つ目と2つ目。

- `src/platform/gitFs.ts`：isomorphic-git に渡すファイルの口（Node の `fs.promises` の形）。失敗は `code`（ENOENT・EEXIST など）で返す。端末用（`CapacitorGitFsBackend`、`works` の下）とテスト用（`MemoryGitFsBackend`）
- `src/platform/gitHttp.ts`：通信の口。GitHub の git の口は CORS を許さないので `CapacitorHttp` で投げ、答えは2進（base64）で受ける。**送る本文は ASCII だけ**（取得は足りる。送信の版の中身は送れないので、混じったら止める）
- `src/platform/bufferShim.ts`：isomorphic-git が使う `Buffer` を npm の `buffer` で置く。`git.ts` が最初に読む
- `src/platform/git.ts`：`shallowClone`（最新の1版だけ）と `removeTree`。動作確認ページに「6. git で取ってくる」
- **エミュレーターで確かめた**：モバイル版のリポジトリを 6.3秒で取得、114 ファイル（手元の `git ls-tree` と同じ数）。中身も読めた。初回は「フォルダーがもうある」で落ちた（isomorphic-git が同じフォルダーを並んで作る）ので、ファイルの口で EEXIST に直した
- **差し替えの形（決めた）**：本体の `core/git.ts` は差し替えない。本体の判断と文言の部品は `core/git.ts` から型しか読まないので、端末用の `src/platform/git.ts` が同じ型で答えを返せばよい（設計書 2.3）

## 9. 中止で通信を切る・版が古い間は台帳を書かない（2026-11-06 夜。枝 `feat/abort-and-stale-gate`、PR #6 の上に積んだ）

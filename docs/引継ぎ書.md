## 1. 共有する部品はいつも本体と同じ版で取り込む

**【決定】** 2026-11-04 作者の裁定（母艦「0.125.4 母艦引継ぎ」から伝達）：本体と共通の部品（`src/models/`・`src/core/`）は「いつも本体と同じ版」で取り込む。本体の版が上がるたびに同じ部品を取り込み、モバイル版を出し直す。

**理由**：作品フォルダーの `設定/` は GitHub で同期するので、本体とモバイル版が同じ台帳を読み書きする。古い部品は台帳の知らない欄を落として書き戻すので、モバイル版が古いままだと、本体で増えた欄が同期で消える。0.123.0〜0.125.4 で投稿の台帳（`models/posting.ts`）に増えた欄（`posts[]` の bodyHash・titleHash・siteEpisodeId・postRef、台帳の revisions、siteFacts の siteWorkNumber）はその例で、本体の注記にも「この欄を知らない古い版が保存すると消える」とある。

`src/ai/`・`src/prompts/` も共有する（設計書 2.2）。台帳を書く部品ではないが、同じ版で取り込む。版をばらばらに持つと、どの組み合わせで確かめたか分からなくなるためである。

## 2. 取り込みの段取り

2026-11-05 に本体 v0.126.2 を初めて取り込み、同じ日に v0.127.0 へ、2026-11-07 に v0.130.3 へ上げた（いま取り込んでいるのは v0.130.3）。仕組みは**本体のタグを指す依存**（`package.json` の `"novel-ai-assistant": "github:nonahisa/novel-ai-assistant#v0.130.3"`）。ワークスペースと比べて決めた中身は設計書 2.2。画面のコードは本体の部品を `src/shared.ts` を通して読む。取り込みも版上げも、次の段取りを守る。

2. **本体の版を決める**：本体の `package.json` の `version` と、それに対応するタグ（`vX.Y.Z`）。タグがまだ打たれていない版は取り込まない（2026-11-04 時点で `package.json` は 0.125.4、タグは v0.125.3 まで）

4. **取り込んだ版を1か所に記す**：`package.json` の `novel-ai-assistant` の `#vX.Y.Z` が唯一の置き場（`pnpm-lock.yaml` が commit まで固定する）。版を上げるのは `pnpm add "novel-ai-assistant@github:nonahisa/novel-ai-assistant#vX.Y.Z"` の1行。画面の動作確認ページの「本体の部品」の行に、取り込んだ版が出る

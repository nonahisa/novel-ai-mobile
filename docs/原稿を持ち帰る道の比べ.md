# 原稿を持ち帰る道の比べ（A：GitHub ／ B：Google ドライブ）

2026-11-07。母艦の頼み（作者の「両方を比べてから決める」）で書いた。

**【決定】A から作る**（作者 2026-11-07 未明。母艦から）。書く台数は「3台以上」。だから B は、本体のドライブ同期が3台以上に対応し、画面から使えるようになってから足す。A は GitHub の API で版を作る道（1章）で作る。本体のドライブ同期が2台だけの作りであることは、母艦が本体のセッションへ伝える。
確かめていないことは「（見立て）」と書き分ける。本体の設計書 5.10 と下書き（`docs/下書き/Googleドライブ同期の比べる案.md`。以下〔番号〕はその8章の出典）は読んだだけで、本体には何も書いていない。

## 0. 先に決めないといけないこと：何台で使うか

**本体のドライブ同期は、いまは2台だけの作り。** 本体の `core/driveSyncEngine.ts` は、ドライブに自分以外の端末のフォルダーが2つ以上あると何もしない（`several_peers`）。前回そろえたときの印が道ごとに1つしかなく、3台目を同じ印で比べると基準が混ざるため（本体のファイルの頭の説明）。モバイル版の側では外せない。

- **母艦＋ノートPC＋スマホの3台**で同じ作品を書くなら、B は本体が3台以上に作り直すまで使えない
- **スマホ＋パソコン1台**なら、いまの本体の作りのまま B を使える（ただし下の 2〜3 の条件つき）

**作者への問い**：同じ作品を、何台で書きますか（母艦・ノートPC・スマホの3台か、スマホとパソコン1台か）。

ほかに B の前提が2つある。

- **1つの作品で GitHub とドライブを併用しない**（本体 5.10.1）。B にすると、その作品はパソコンの側も GitHub からドライブへ切り替える
- **本体のパソコンの側も、まだ画面から使えない**（5.10.5 の段階3が残り。作者の Google Cloud の準備と2台の往復も未）。中身は 0.131.0・0.132.0 にあるが、**タグが付いた最新は v0.130.3 なので、モバイル版はまだ取り込めない**（「タグごとに取り込む」決まり）

## 1. A の中身を見直した：端末の部品は要らない見込み

引継ぎ書では A を「git の送信の2進の本文を、端末の部品（Kotlin・Swift）で送る」としていた。もう1つ、**GitHub の API で版を作る道**がある。

- `api.github.com` の `git/blobs`（中身を base64 の JSON で送る）→ `git/trees` → `git/commits` → `git/refs` の更新（早送りだけ。向こうが進んでいれば断られる）
- `api.github.com` は CORS を許す（`*`。POST・PATCH、`Authorization` の見出しも可）。**2026-11-07 に `https://localhost`（Android）と `capacitor://localhost`（iOS）の両方で確かめた。** だから WebView の `fetch` で送れ、2進の本文の壁に当たらない
- サインイン（デバイスフロー）の `github.com/login/...` は CORS を許さない（同日に確かめた）が、本文は文字（フォーム）なので今の `CapacitorHttp` で送れる
- 送ったあと、手元の isomorphic-git の記録を向こうへ合わせるため、取得をもう1回する（小さい）
- 1つの中身の大きさの上限は確かめていない（見立て：原稿の1話なら足りる）

以下の A は、この道（A-JSON）で数える。

## 2. 5つの観点

| 観点 | A：GitHub（A-JSON） | B：Google ドライブ |
|---|---|---|
| 作者の手間：作る準備 | github.com で OAuth App を1つ作る（フォーム1枚。デバイスフローを入にする）。スマホで一度サインイン | Google Cloud のプロジェクト・同意画面・テストユーザー（作者）・**Android 用の OAuth クライアント（パッケージ名と、署名の鍵の SHA-1。試しの鍵と配る鍵で別）**・**iOS 用のクライアント（バンドルID）**。パソコンの側の準備（デスクトップのクライアント）も別に要る |
| 作者の手間：毎日 | ［保存・同期］を押す。サインインは切れない（OAuth App のトークンは期限なし。見立て：期限を付ける設定は入れない） | ［保存・同期］を押す。**「テスト中」の間は7日で許可が切れ、許可し直す**〔10〕。本番へ出すにはプライバシーポリシーなどの用意が要る（見立て） |
| 作る量と時間（見立て） | サインイン 1〜2日・送る道 2〜3日・食い違いの扱い 3〜5日・鍵の保管 1日。**本体を待たずに始められる** | 本体のタグを待つ。Google のサインインは**端末の部品が要る**（Android は独自の URI での戻りが使えず〔9〕、`AuthorizationClient`〔14〕。iOS も別に。2〜4日）。同期の中身は本体の部品を使えるので、手元の読み書きの口と画面で 2〜3日。**3台で使うなら、本体の作り直しが先** |
| 台帳と原稿を壊す危なさ | git の履歴が全部残り、間違えても戻せる。ただし**食い違いの扱い（見比べて残す文を選ぶ）をモバイル版で作る**（isomorphic-git の混ぜる機能は弱いので頼らない。設定の台帳は本体の `decideSettingsConflict` を使う）。ここが一番の作る所で、間違える余地もここ | 本体の作りが守りを持つ（90通りの組み合わせで見逃し0・誤検出0のテスト・向こうで消えても消さない・届ききるまで書かない）。手元へ書くのは今の `textFile.ts` の書き戻し（文字コードと改行を保つ）を本体の口に差すだけ。**ドライブには履歴が無く**、前の版へ戻す手は手元の退避の写しだけ（見立て：ドライブの版の履歴は確かめていない） |
| 本体との揃え方 | パソコンの今の GitHub 同期と同じリポジトリに積むので、**作者の今の使い方のまま**。ただし食い違いの扱いはモバイル版の別の作りになり、本体の規則（6.15 など）に合わせ続ける手間がある | **同期の中身が本体と同じ部品**（`core` を取り込むだけ）。揃え方は一番よい。ただし本体の段階と版に縛られる |
| iOS でも通るか | 通る見込み。`api.github.com` は iOS の出どころでも CORS を許す（確かめた）。デバイスフローは `CapacitorHttp`。**端末の部品は要らない** | 通信は通る（ドライブの API・アップロード・トークンの口が `capacitor://localhost` を許す。2026-11-07 に確かめた）。**サインインは iOS 用の端末の部品か、別の作りが要る**（調べていない。見立て） |

どちらでも、**版が古い間は設定の台帳を書かない関所**（`LedgerWriteGate`）はそのまま効く（`設定/` はどちらの道でも同期するため）。

## 3. おすすめ

**いまは A（A-JSON）。B は、本体のドライブ同期が画面から使え、3台以上で使えるようになったら足す。**

理由：

1. 本体のドライブ同期は2台だけの作りで、母艦・ノートPC・スマホの3台では止まる（0章）。2台でも、パソコンの側がまだ画面から使えず、タグも無い。B は本体の予定に縛られる
2. A は作者の今の使い方（パソコンは GitHub で同期）を変えない。作品をドライブへ切り替える必要が無い
3. 作者の準備は A がずっと軽い（OAuth App のフォーム1枚 ／ Google Cloud の数か所と、スマホ向けのクライアント2つ）。毎日の手間も、A は7日ごとの許可し直しが無い
4. A-JSON なら端末の部品（Kotlin・Swift）が要らず、iOS も同じ作りで通る見込み。B は Google のサインインに端末の部品が要る

A の弱み（食い違いの扱いをモバイル版で作る）は、本体の規則と `decideSettingsConflict` を部品として使い、本体の再現テストの考え（見逃しと誤検出を数える）を写して抑える。

**スマホ＋パソコン1台で使う、と作者が答えたなら**、B の弱みは「本体のタグ待ち」と「準備の重さ・7日の許可し直し」だけになる。そのときは、本体の段階3が済むまで A で作り、済んでから B を足す順を勧める（A で作るサインイン・鍵の保管・食い違いの画面は B でも使い回せる見込み）。

## 4. 始める前に確かめること（A に決まったら）

- `git/blobs` の大きさの上限と、`git/refs` の更新が早送りでないときの断り方（公式の頁で）
- API で作った版を、パソコンの git がふつうに取り込めること（作者の作品の写しで1回）
